# Mobile attack-alert and notice separation

A retained mobile image showed a general notice painted over the existing attack button. The same defect was reproduced on the accepted v0.65 code at 844×390, 640×360 and 390×844 logical viewports. This is a visual collision, not evidence that a particular ordinary loss was caused by a missed warning.

At widths with room for both controls, the attack warning uses the space beside the current objective. On narrower screens the general notice sits below the warning while it is present, then returns to its usual position. No new panel, information, alert, command, sound or gameplay rule is added. The existing alert still focuses the endangered worker.

Native Compatibility/llvmpipe before/after captures use one controlled M1 worker-hit setup, a representative long notice, the same seed/camera and synthetic touch. All three former overlaps are absent. Alert taps focus the worker while preserving the selected soldiers and their orders. Alert disappearance restores the narrow-screen notice position. Portrait also uses top/bottom safe insets. The portable fixture writes to user://mobile_alert_review; the capture run used an external output path only.

Real phone/browser rendering and human first-time response remain untested. The ordinary M3 worker losses remain an allocation/observation-limited result; this fix does not prove a different combat outcome. This checkpoint follows v0.65 and is not included in its frozen release.
