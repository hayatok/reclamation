# 拠点へ視点を戻しても進軍先が分かる

広い第2作戦で、部隊へ指示したあと本部を見ると、従来は短い点滅が消えて「移動中」という文字だけが残りました。選択中の部隊に同方向の移動・攻撃移動がある場合、地図へ指示先の旗と1人の実際の経路を表示します。世界や常時HUDに文章は足していません。

## 表示の意味

- 小さな丸で示した1人の現在経路です。複数人の道を平均したり、全員が同じ道を通ると保証する線ではありません。
- 旗は現在の移動指示先。未知の場所へ指示した旗も表示しますが、道の安全性や到達を保証しません。
- 経路線は最初の未踏セルで打ち切り、未知の障害物・敵・感染源から情報を読みません。旗へ向けた架空の直線を補いません。
- 同じ種類の移動命令、近い指示先、現在有効な移動経路を持つ戦闘員だけの選択に限定します。混在・停止・到着・経路再計算中・経路なしでは消えます。
- 経路点96、視界セル参照768などの上限があります。非常に長い既知経路でも線が途中で止まる場合があり、停止原因を示すものではありません。

## 実画面で確認したこと

通常攻略から東岸の4人をCtrl1へ登録し、地図の右クリックで西岸へ帰還指示、左クリックで本部へ視点を移しました。9秒後に一時停止して保存し、その状態を再開しました。[変更前](evidence/squad_route/before.png)は「移動中」だけ、[変更後](evidence/squad_route/after.png)は橋を通る線と旗を確認できます。同じ一時停止状態で描画だけを切り替え、全保存状態と経路探索数の一致を確認しました。

本部選択で消えること、部隊キーで戻ること、停止で直ちに消えることを通常キー入力で確認しました。[844×390のタッチ表示](evidence/squad_route/mobile_844x390.png)でも64×64の地図内に収まり、命令欄を覆いません。これはクラウドのネイティブ表示試験であり、実スマホ/Safariでの操作確認ではありません。

## 正確さとコスト

描画処理は新しい経路を探索せず、現在の移動管理が確定した経路を読みます。地形変更時は既存のnavigation revisionで古い経路を抑止します。開発中に見つかった境界の丸めによる未知セル参照は、描画側の障害物再検査を取り除いて解消しました。

同じ状態の描画はキャッシュを使い、選択・命令・位置・経路・視界・ナビゲーション状態が変わると更新します。一時停止中の操作でも古い表示を残しません。120点の合成経路、2,000回のCPU測定では、4人の変化なし0.048ms／移動tick0.729ms、64人では0.510ms／1.587msでした。経路探索の追加は0です。これはヘルパーだけのCPU値で、ゲーム全体やWebのfpsではありません。

再現用の通常保存は `tests/fixtures/earned_squad_return.json`、限定試験は `tests/check_selected_squad_route_cue.gd`。表示レビュー用scriptは隔離したuserdataで実行します。既存の兵数・速度・費用・攻撃・霧判定・セーブ形式は変更していません。人間の初見理解や実端末の快適性は未確認です。
