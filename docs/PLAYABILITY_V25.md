# 0.25：建設の判断、部隊の分割、戦闘後の街

この版は、通常のマウス・キーボード操作で第一作戦を通して遊んだときに見つかった、判断と操作の迷いを減らす改修です。開発候補であり、市販品質の認定や初見プレイヤーによる評価ではありません。

## 実際の進行

基盤0.24の第一作戦を、新規開始から資源採取・増員・住居と生産施設・段階II/III・揚水場の復旧・達成まで通常UIで進めました。途中で守備を偏らせて作業員と経済施設を失いましたが、残った本部・部隊・資源から再建できました。結果はゲーム内21分18秒、2,213撃破、Lv27です。資源付与や強制勝利は使っていません。操作担当はエージェントで、確認のため戦術停止を多用しています。一般の人の初見操作時間を示すものではありません。

## 変わったこと

- 建設中の完成モデルを縦に縮める表示をやめ、資材・開いた骨組み・部分屋根や設備・完成形に分けました。実操作では74%の工房を完成済みと見誤り、作業員を移してしまう場面がありました。[同一の有料建設状態による比較](CONSTRUCTION_VISUALS.md)。
- 集中攻撃の後に兵士が同じ場所へ重なる問題を修正しました。停止中・射撃中の戦闘員が通行可能な小さな範囲で間隔を取り、通常の左クリックとShiftで部隊を分けられます。移動経路、作業員の作業場所、輸送車の運行を置き換える機能ではありません。
- 建築できない理由が施設や発展段階なら、ボタンにその条件を表示します。資材不足の場合は、従来どおり必要量と不足資源を表示します。無効なショートカットを押した場合も、必要な条件を示します。
- 結末の生活再建場面へは約0.55秒の画面切替で移ります。残っていた感染群・砲弾・戦闘エフェクトは結末の表示から外し、生存者と建物は残します。追加の撃破、XP、報酬は発生しません。次の作戦・再挑戦・作戦選択は最初から操作できます。

## 確認範囲

建設表示だけを変更した比較では、通常費用で建てた住居・訓練所と途中保存を含む21時点のゲーム状態が一致しました。完成モデルのスケールを変えず、途中保存から建設段階を再生成します。

部隊間隔は、実際の重なった保存状態、通常の移動・攻撃移動・集中攻撃・停止、狭い通路、塞がれた壁、射程、移動速度、作業員と輸送車、保存再開を確認しました。統合候補のネイティブ画面でも、1人の選択、Shiftで2人へ追加、独立した移動を確認しています。新たな経路探索や乱数消費は加えていません。

3作戦の結末表示、即時の次へ・再挑戦・作戦選択、保存失敗時の再試行、敗北画面を確認しました。暗転と表示整理の前後で、ゲーム状態・乱数・XP・撃破・飛翔中の砲弾データは変わりません。集中検証は tests/check_combat_spacing.gd（--candidate）、check_combat_spacing_safety.gd、check_command_block_reasons.gd、check_aftermath_transition.gd、check_ending_controls.gd にあります。保存に触る検証には新しい隔離プロファイルを使ってください。

短時間のheadless終了ではObjectDB等の解放警告が残ります。実プレイ中の例外や保存消失を示すものは今回確認していませんが、長時間のメモリ評価済みとは扱いません。クラウドの描画はMesa llvmpipeによるソフトウェア描画です。実GPU、macOS実行、Web実行、音の実聴、初見の人による操作と難易度評価は未確認です。
