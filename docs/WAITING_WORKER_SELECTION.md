# 待機作業員のまとめ選択

広域第2作戦の通常攻略セーブ（720.35秒）には作業員14人がおり、5人が同じ位置で待機、9人は採取・移動中だった。従来は次の1人を呼ぶか、働いている人を含む全14人を選ぶ必要があった。

既存のスマホ選択欄に「待機 5人を選択」を追加した。PCは上部の待機ボタンまたはピリオドにShiftを併用する。通常操作の1人ずつ選択は維持する。対象判定は既存の待機・採取停止・経路なし判定を使う。

選択だけでは作業、運搬物、予約、資源を変更しない。通常セーブで5人のみの選択、9人の作業継続状態、部品を持つ作業員の荷物保持、選択の保存再開を確認した。844×390と390×844の合成タッチ入力でボタンから選択し地図に戻る動作を確認。クラウドの実Godot画面を同じセーブで前後比較した。

人による初見評価、実スマホ、Web/Safari、Macでの操作は未確認。待機に至った原因はこの保存状態だけから断定しない。短時間headless終了時のObjectDB警告が縦画面の検証で残る。
