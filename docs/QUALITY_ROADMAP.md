# 品質改善の範囲と採用基準

荒廃都市を内政で育てた生存者の力で取り戻すRTSを軸に、次の5項目を段階的に実装します。作業量や版番号ではなく、判断・操作・読み取り・成長の実際の変化で採用を決めます。新しい機構を一度に重ねません。

## 1. 作戦ごとの戦略を変える

第2作戦は、広域の偵察・資源地への進出・感染源の破壊へ変更しました。通常費用の一連の指揮と実保存からのネイティブ再開を確認しています。[現在の根拠と未確認範囲](FRONTIER_MISSION.md)。第1/3作戦の目的は保持します。固定位置の廃棄倉庫を費用付きで復旧する選択を追加し、護衛して進出・復旧・最初の搬入まで通常費用で確認しました。

採用条件は、地図が大きいだけでなく、遠方での搬入・防衛・偵察の判断が実際に使われることです。早期攻撃と研究後の攻撃の優劣や人間の楽しさは未検証。旧輸送作戦の段階II出発と狭い採取地配置は未採用の履歴として残し、広域作戦の成功根拠へ流用しません。

## 2. 経済と補給の詰まりを読めるようにする

補給不足の短い表示は実装済みです。待機班だけを一括選択する入口も追加しました。現在の選択欄にある停止理由、上部の担当人数を再利用します。足りない情報は実際の補給/消費と、停止している施設や仕事の関係です。備蓄の差だけから、購入を収入減と誤認しないようにします。

採用条件: 実際に記録された生産・消費・停止状態と表示が一致し、回復時には古い問題を残さないこと。既存欄に短くまとめ、常時の数字や警告の壁を増やしません。

## 3. ランダム成長の選択を戦い方へつなげる

24強化、電撃/爆発/機動などの系統、密集への重火器、重装への貫通は既存です。既存の系統補充への影響を選択前に示しましたが、戦術の多様性を証明したものではありません。まず同条件の獲得済み/自然に獲得する候補で、編成・位置取り・資源投資にどう差が出るかを比較します。

採用条件: 新しい名前や数値を足すだけでなく、選び分ける局面が説明できること。大群を圧倒する完成ビルドを、強いという理由だけで弱体化しません。AIの勝利を人間の楽しさの証明とはしません。

## 4. 終末都市の画作りと撃破の読み取り

復旧前後の倉庫と感染源の造形を、通常距離の同場面比較で改めました。大きな地形、作戦のランドマーク、明暗、通常倍率の人物動作と大群の崩れ方を優先します。小物の追加や色替えだけを品質改善の成果にはしません。

採用条件: 同じ場面/カメラで前後比較し、部隊・目標・接近路と撃破結果が読めること。敵数を黙って減らさず、群れに高価な個別物理処理を増やしません。描画環境と追加コストを明記します。効果音の数を増やす前に、実聴による評価が必要です。

## 5. 敗北から再挑戦へつなげる

既存の再挑戦を保ち、直前に実際に起きた2〜3の出来事を示す表示は実装済みです。工房や採取班の損失、弾薬切れなどを時刻とともに記録し、推測を敗因として断定しません。

採用条件: 記録と表示が一致し、同じ損失の重複、プレイヤーの解体を敵の破壊とする誤記、前回作戦の記録混入がないこと。途中保存/再開も検証し、通常の操作画面へ新しい警告群を増やしません。

## 共通の公開条件

- 関連する通常操作、保存/再開、中断/再試行を検証し、同じ場面の画像・必要なら映像を残す。
- ソースと配布物を保存し、保存先から再読込してハッシュを確認する。ローカルだけの準備を外部保全済みとは呼ばない。
- GitHubの確定コミットと配布来歴を一致させ、Release後のPages CIと配信ファイルを確認する。
- 実Web/スマホ/Mac/GPU、音の実聴、人間初見の評価が未確認なら明記する。商用品質の完成と同一視しない。
- 作業予約、部隊登録、ミニマップ命令、継続護衛、選択別メニュー、成長の保留など、既存の機能を重複して作らない。
- 正式版前の過去セーブ互換は公開条件にしない。現行版の保存が壊れないことは別に確認する。
